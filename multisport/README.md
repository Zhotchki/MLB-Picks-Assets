# MultiSport Pick’em v0.5.2

Dedicated app: https://zhotchki.github.io/MLB-Picks-Assets/multisport/

Source of truth: this directory on main in Zhotchki/MLB-Picks-Assets. This app is separate from the existing MLB app. Future assistant updates can use the connected GitHub tools directly. No copying Apps Script files or manual spreadsheet entries is required for this adapter.

## Automatic operation

`.github/workflows/update-multisport.yml` runs every 15 minutes and when adapter code changes. Scheduled Actions are best effort and can be delayed. It retrieves the existing MLB Apps Script JSON endpoint directly, checks age of BOTH snapshot and underlying projection refresh, validates current games and player identities against MLB StatsAPI, captures the first pregame forecast permanently, grades final batting results, and updates the frontend JSON. Failed network runs leave previous data intact. The UI hides data older than 45 minutes and stale upstream forecasts. MLB’s existing Apps Script refresh is an upstream dependency; this workflow does not install an Apps Script trigger.

`ledger.json` contains model forecasts, not user wagers or personal information. Capture once per game/player/prop/threshold; do not overwrite probabilities after seeing results. Postponed/cancelled games and players with no plate appearances are void. Same-name matching requires a unique identity on the specified team and game. Doubleheaders are excluded until upstream game IDs are available.

Mondays: candidate additive calibration offsets are fitted on earlier complete games. Minimum global support is 200 training player-games and 50 holdout player-games; multiple thresholds or props do not create more independent player-game support. Groups are sport/prop/direction/source-version specific. Each changed group requires 50 training player-games, 25 holdout player-games, 10 training games and five later holdout games. Residuals are averaged within player-game, with 50 pseudo-observations of shrinkage. Brier and log loss average targets within player-game, then players within game, then across games. Every changed group must improve both scores by at least .001, and the combined candidate must also improve both scores by .001. Unchanged/rejected group offsets are preserved. Holdout games must be newer than incumbent training. Immutable captures with inconsistent/missing settlement evidence are excluded. Review versions and diagnostics are saved; promoted offsets affect future captures only. This calibration stage does not validate NBA/NHL betting probabilities or remove their platform gate. Repeated weekly model selection still needs independent prospective evaluation.

## Current limits and next implementation

All four source adapters are connected. MLB/NFL retain upstream forecasts; NBA/NHL provide explicitly unvalidated count baselines, excluded from platform matching. NBA preseason games are excluded. Current MLB Reference Line values are empty; Probability Threshold is a MODEL TARGET, not a Sleeper/platform line. Only observed Sleeper lines at an identical model threshold can enter the slip search; no payout is inferred. Never turn a target into a fictitious line or describe reciprocal probability as an actual payout.

The platform key is connected. Sleeper rows with missing native offer types are flagged for review, and payout terms must be confirmed in Sleeper. Validate NBA/NHL baselines on later, separate games before enabling platform eligibility; a pooled weekly calibration improvement alone does not establish sport-specific model validity. Mixed-sport slip search is already implemented for matched eligible offers, without duplicate players or games. Baseline forecasts do not establish a globally highest win probability or a proven betting edge.

Run checks: `python -m unittest discover -s multisport -p 'test_*.py'`; update: `python multisport/update.py`. Runtime uses Python 3.12 stdlib, no credentials or paid dependencies.

NFL results are graded against final scheduled scores plus matching GSIS/season/week/team/opponent stats from nflverse. Missing rows or stats remain pending, never inferred as losses. NFL source failures do not block MLB updates.

Live lines connector: ParlayAPI's documented /v1/sports/{sport}/props endpoint, scoped to Sleeper, for MLB/NFL/NBA/NHL. It reads PARLAY_API_KEY from repository Actions secrets (now connected). Never place the key in source, a public file, or chat. Personal key setup: https://parlay-api.com/ ; repository secret settings: https://github.com/Zhotchki/MLB-Picks-Assets/settings/secrets/actions . Default cadence shares up to eight calls per UTC day across sports with eligible forecasts: four sports every 12 hours, two every six hours, one every three hours. Baseline-only sports are not polled by the app. Hard defaults are 24 reserved credits/day and 900/month; 31 steady-state days reserve at most 744 credits. Provider usage/remaining headers can stop requests earlier when other usage consumed the account allowance. No automatic pagination, paid subscription, or credit purchase. Failed requests consume the same reserved daily and monthly budget as successful requests. Documentation claims a 1,000-credit free tier; coverage and pricing need confirmation with the actual account. Cadence/budget overrides use PICKEM_REFRESH_MINUTES / PARLAY_MONTHLY_CREDIT_CAP / PARLAY_DAILY_CREDIT_CAP and still enforce configured caps. Budget-limited polling means offers disappear after 15 minutes; it is not a continuously current board.

The authenticated /props path now returns Sleeper rows for MLB/NFL/NHL; NBA board was empty during preseason. Real rows omit kickoff and native type, handled as described in v0.5.2. Contract tests also cover fixture ambiguity, type flags, strict line matching and freshness. Board diagnostics preserve truncation/degradation/has-more flags; do not claim exhaustive coverage. No key: forecasts, result grading and model review continue without live-line requests.

Match a FULL-game Sleeper offer with canonical event ID, known market, unique player identity, verified fixture, and observation age <=15 minutes. Source-declared standard offers are accepted. Native-type-absent DFS rows are flagged for review, never classified as standard; explicit special types are excluded. Kickoff can come from a reported provider time or a unique official dated fixture. Match the EXACT model line; no interpolation or assigning a forecast probability to a different platform line. Price fields from DFS midpoint/effective conversions are not used as estimated win probabilities or payouts. Unknown period or unresolved fixture/time is excluded. Missing native type requires the explicit review flag and cannot supply payout/settlement terms. NBA/NHL baselines remain ineligible for playable offers even when their boards are observed.

Slip search supports 2/3/4/5/6/8 legs, 200-offer pool, 128 beam states per leg count and up to five returned slips per size. No repeated player or game; Sleeper offers only. Joint probability assumes independence across games, excludes same-game combinations, and is explicitly labeled an estimate. This is a bounded search of matched available offers, not a proven global optimum or learned correlation model. Source payout unavailable means no payout is displayed. The result ledger remains a forecast ledger; provider-specific wager/slip settlement needs a separate ledger in a future release.

## v0.4: NBA and NHL baseline adapters

NHL reads league-owned api-web.nhle.com schedules, season rosters, current club statistics, regular-season player logs and final boxscores. ESPN injury reports supply a separate availability exclusion; every listed injury, including day-to-day, is excluded. Injury-report timestamps must be within one hour; failure to verify injuries stops that sport's collection. No lineup is claimed confirmed. Coverage is deliberately bounded to eight leading current-season shooters per team and scheduled regular-season games in the next 48 hours.

NHL shots-on-goal targets are 1–5 (hypothetical MORE lines 0.5–4.5). Require at least two current-season appearances, 25 valid same-team games from current/prior seasons (last 60 within 400 days), an appearance within seven days, 12–35 expected minutes on ice, and recent TOI within 25% of historical TOI. Expected TOI is the mean of up to five recent current-season games. A pooled shots-per-minute rate supplies the projection; a negative-binomial approximation uses historical counts scaled to expected TOI for dispersion, falling back to Poisson when variance is no greater than the mean. This is a descriptive count baseline without matchup strength, confirmed line combinations or a fitted injury impact. Support counts are historical games, never described as calibration samples.

NBA reads ESPN schedules, current team rosters, injuries, regular-season player game logs and final summaries. Preseason and postseason are excluded. Require at least three current-season games, 25 same-team games, an appearance within seven days, 15–40 expected minutes and recent minutes within 25% of historical minutes. Only active roster identities without listed injuries qualify. History must identify completed wins/losses and be at least four hours old; missing stats, wrong teams/seasons and live games are excluded. Count baselines cover points, rebounds, assists and made three-pointers at specified model thresholds, using the same rate/dispersion approach. They are not validated matchup predictions. Preseason is excluded automatically; current-season support must accumulate after regular-season play starts.

Both new sports set probabilityStatus=UNVALIDATED_BASELINE and platformEligible=false. They can be viewed and captured prospectively, but the platform matcher explicitly rejects them even at a matching line. Do not remove this gate merely because the API key is connected or pooled calibration improves. Verify model validity and calibration per sport/prop on chronological unseen games first. Scores and DNP handling are forecast settlement rules, not platform wager settlement: final boxscore identity/team/season required, explicit no-playing-time rows void, missing rows pending, verified zero counts can be losses.

All sources are independently isolated. Caches persist through Actions, source reads are bounded in parallel, and expired data is not silently reused for these new adapters. A cold first import can take longer; workflow timeout is 20 minutes. After network imports, the pipeline rechecks kickoff and records the actual capture time, so an import that crosses kickoff cannot backdate a forecast. Weekly maintenance must preserve these guards, the standalone MLB/NFL apps, ledger immutability and provider budget.

## v0.5: per-sport/prop prospective validation

The automatic data feed now includes validation reports derived from the immutable ledger. Report identity separates sport, prop, direction, source/baseline version and the frozen per-group correction. New captures store a stable calibration-group identifier, so unrelated changes to the global model release do not fragment an unchanged prop correction. Global release versions remain visible; legacy captures without this identifier stay separated by their stored model version. Captures must precede kickoff; grades must follow kickoff and agree with the stored actual/stat threshold. Duplicate IDs retain the first qualifying capture. Pending and void rows never become losses. Reports identify inconsistent results and invalid captures instead of silently using them.

Scores use the frozen probability captured before the event. Multiple targets are first averaged within player-game, then within game; event averages receive equal weight. Support counts explicitly distinguish forecast rows, unique player-games, separate games and game dates. Projection MAE/RMSE/bias use one observation per player-game for each prop/version group, avoiding repeated-threshold inflation. Model-target hit rate is not a platform wager win rate.

Chronological evaluation reserves the final 20% of complete events as holdout. Reviewable minimums: 200 training and 100 holdout player-games, 25 training and 10 holdout games, seven training and three holdout game dates in America/Chicago. All players and thresholds in an event remain on one side. A smoothed constant-per-target reference is fitted only to training outcomes; each holdout target requires at least 30 training player-games. Report holdout Brier/log-loss improvements and whether both beat the reference. Reviewable support or beating a reference is exploratory evidence, not proof of calibration, generalization or betting edge. No report status automatically enables baseline offers. The Model results view exposes progress, source/model versions, actual forecast metrics and projection error, with filters by sport.

Tests include cross-sport harm hidden by pooled improvements, retention of rejected group offsets, fresh-holdout protection, separation of source versions, duplicate provenance, strict fractional lines, no threshold-count support inflation, no fake zero metrics, display escaping and train-only reference fitting. The workflow runs Python checks and both browser-logic check sets before publishing feed updates.

## v0.5.1: actual Sleeper rows and official fixture resolution

Live provider rows omit kickoff and native projection type. A missing kickoff is resolved only when a verified MLB StatsAPI or nflverse schedule supplies exactly one game for the source's explicit game date and ordered home/away teams. Missing dates, teamless rows, reversed teams, ambiguous fixtures and contradictory timestamps remain excluded. Explicit provider kickoff is checked against the verified forecast within five minutes. Player identity, full-game period, freshness and exact model line are still required. Current adapters retain official game date and NFL home/away identity; no schedule metadata is invented for old ledger captures.

Missing odds_type/projection_type is NOT classified as standard. An explicitly identified Sleeper DFS row with no native type evidence can be shown as a line-matched review candidate with platformOfferType=unreported and requiresPlatformReview=true. Every resulting slip and affected leg displays the review requirement; confirm offer/settlement/payout terms in Sleeper. Explicit special types, null/inconsistent type tags and unvalidated NBA/NHL baselines are excluded. No payout multiplier or automatic wager is supplied. Documented/observed market aliases map only equivalent stats and never alter the line or probability.

The workflow checks out current main when rerun to avoid publishing data from an old commit. HTTP failures publish only numeric status and safe error categories, with a 15-minute retry interval; no key, response body or exception text is published. Successful board polling now shares the allowance among eligible sports as described below. Cached lines still expire after 15 minutes, so this budget does not provide continuously current slips.
